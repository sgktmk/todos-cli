# TUI 仕様

要件定義書 18 章「TUI機能」および 25.6「TUIの画面仕様」の詳細。

## 位置付け

キーボード中心で操作するタスクダッシュボード。
汎用 Markdown エディタや Vim 互換エディタとしては実装しない。
複数行の本文編集は外部エディタへ委譲する。

Markdown の書き換えは CLI と同じ `ops` / `schedule` / `validate` を経由する。
TUI が独自にファイルを書き換えることはない。

## 起動

```sh
todos
todos tui
```

起動時に再配置またはアーカイブが必要と判断した場合、確認する。
`--no-prompt` を付けると確認しない。詳細は「再配置の提案」を参照。

起動時は **タスクがある最初のセクション** を選択する。Today が空でも
「タスクが1件も見えない画面」にならないようにするため。全セクションが空の場合は
Today を選択する。

## 画面レイアウト

```
 トドズ  ~/todos/tasks.md                 ○5  ◐2  ◆1  2026/07/28 (火)
╭─ Sections ───────╮╭─ Tasks / Today ─────────────────────────────╮
│ ● Today        4 ││▍ ◆ 要返答（山田）  レビュー対応 〜2026/07/28│
│ ● Tomorrow     1 ││  ◐ 進行中  API を実装 〜2026/07/29 #api ≡   │
│ ● InWeek       2 ││  ├ スキーマを決める                         │
│ ● OpenEnded    1 ││  ╰ ハンドラを書く                           ┃
│ ● ParkingLot   5 ││  README を書く                              ┃
╰──────────────────╯╰─────────────────────────────────────────────╯
 j/k:移動  J/K:セクション  Tab:ペイン  Enter:詳細  ?:ヘルプ  q:終了
 Today  1/6                                                    全て
```

- 最上行（ヘッダ）: 名前・tasks.md のパス・未処理タスクの内訳・基準日
- 左ペイン: セクション一覧と件数（トップレベルのタスク数。0 件は `·`）
- 右ペイン: 選択中セクションのタスク。子タスクは枝記号を付けて字下げする。
  詳細文を持つタスクには行末に `≡` を付ける。
  表示しきれない場合は右枠がスクロールバーになる
- 下から 2 行目: キーヘルプ（端末幅に合わせて表示する項目を減らす。
  `?:ヘルプ` と `q:終了` は幅が狭くても必ず残す）
- 最下行（ステータスバー）: セクション名 / 現在位置 / 操作結果メッセージ /
  表示位置（全て・先頭・末尾・％）

選択行は帯状に強調する。フォーカスの無いペインの選択行は控えめな帯にする。
枠とタイトルはフォーカスのあるペインだけアクセント色にする。

タスクが 1 件も無いセクションでは、右ペインに
`タスクはありません  J/K または Tab でセクション移動` と表示する。
検索結果が空の場合は `該当なし  Esc で解除` と表示する。

## 配色

配色は `todos/theme.py` に「役割名 → 色」の表としてまとめる。描画側は色番号を
持たない。

- ステータス: 要返答=赤、進行中=橙、回答待ち=紫、未着手/保留/やらない=灰、完了=緑。
  記号（`◆ ◐ ◇ ○ ▪ ✓ ✗`）を前置する
- 期日: 期限切れ=赤、当日=橙、当週=黄、それ以降=青緑
- タグ: 淡い青紫。詳細文の `≡` は淡色。セクション名の記号はセクションごとに色を変える
- 背景は塗らない（端末の背景色をそのまま活かす）。塗るのは選択行・ヘッダの
  名前・ステータスバーだけ

| 環境変数 | 既定 | 説明 |
| --- | --- | --- |
| `TODOS_TUI_THEME` | `dark` | `dark` / `light` / `basic`（8色） / `mono`（色なし） |
| `TODOS_TUI_GLYPHS` | `1` | `0` で記号と罫線を ASCII に落とす |
| `TODOS_TUI_POWERLINE` | `0` | `1` でステータスバーを Nerd Font の区切りにする |
| `NO_COLOR` | — | 設定されていれば色を使わない（[no-color.org](https://no-color.org/)） |

256 色を扱えない端末は自動的に 8 色パレットへ、色を扱えない端末は反転・太字・
淡色の属性表示へ落とす。記号を落とした場合、ステータスは従来どおり
`【進行中】` の形で表示する。

## キー割り当て

| キー | 動作 |
| --- | --- |
| `j` / `↓` | 次のタスクへ（末尾まで来たら先頭へ戻る） |
| `k` / `↑` | 前のタスクへ（先頭まで来たら末尾へ戻る） |
| `g` / `G` | 先頭 / 末尾へ |
| `Tab` | Sections ペインと Tasks ペインを切り替える |
| `J` / `K` | 次 / 前のセクションへ（端まで来たら反対側へ回る） |
| `Enter` | タスクの詳細を表示（Sections ペインでは Tasks ペインへ移る） |
| `a` | タスクを追加（トップレベル。期日を入れるか聞くことがある） |
| `o` | 選択中のタスクの子として追加 |
| `c` | タスク行を複製（詳細文・子タスクは複製しない） |
| `[` / `]` | 兄弟の中で上へ / 下へ動かす（`Shift` + `↑` / `↓` も可） |
| `i` | タイトルを簡易編集 |
| `I` | 詳細文を編集（外部エディタ） |
| `D` | 期日を設定・削除（空欄で削除） |
| `T` | タグを編集（空白区切り・空欄で削除） |
| `s` | ステータスを変更（相手は空欄で削除） |
| `d` | 完了にする |
| `x` | やらないにする |
| `m` | セクションを移動 |
| `/` | キーワード検索 |
| `t` | タグ検索 |
| `Esc` | 検索結果を解除 |
| `r` | 自動再配置 (rollover) |
| `A` | アーカイブ |
| `w` | 構文上の警告を表示・修正 |
| `e` | 外部エディタで編集 |
| `R` | ファイルを読み直す |
| `?` | ヘルプ |
| `q` | 終了 |

キー割り当ての変更は MVP 対象外。

### ペインと一覧の移動を分ける

- **ペインの行き来は `Tab` だけ**。`h` / `l` と `←` / `→` は割り当てない。
- **`j` / `k` はいま見ている一覧の中だけで循環する**。末尾で次のセクションへ
  抜けない（空のセクションでも抜けない）。読みながら押し続けたときに、
  どのセクションを見ているのか分からなくなるため。
- **セクションの移動は `J` / `K`、または `Tab` で Sections ペインへ移って
  `j` / `k` で選ぶ**。どちらも端まで来たら反対側へ回る。
  Sections ペインでの `Enter` は「このセクションを見る」とみなして
  Tasks ペインへ戻る（`Tab` と同じ）。

## 項目ごとの編集手段

タスクの各フィールドをどこから編集できるか。表示されているのに編集できない項目を
残さないことを方針とする。

| 項目 | 表示 | 編集 |
| --- | --- | --- |
| タイトル | 行・詳細モーダル | `i` |
| ステータス | 記号つきで行に出る | `s` / `d` / `x` |
| 相手（要返答・回答待ち） | `【要返答（山田）】` | `s` の流れで入力。空欄で削除 |
| 期日 | 行・詳細モーダル | `D`。空欄で削除 |
| タグ | 行・詳細モーダル | `T`。空白区切りで差し替え、空欄で削除 |
| 詳細文 | `≡` と詳細モーダル | `I`（外部エディタ） |
| 子タスク | 枝記号つきで行に出る | `o` で追加。並べ替えは `[` / `]`、削除は `e` |
| 並び順 | 上下の位置 | `[` / `]` で兄弟の中を移動 |
| セクション | 左ペイン | `m`（`D` で期日を変えたときは自動追従） |
| チェックボックス | 出さない | ステータスから導出。ずれは `w` で検出・修正 |
| 取り消し線 | やらない色で表現 | 同上 |
| 箇条書き記号・`【未着手】`の明示 | 出さない | 元の表記を保つための情報。編集しない |

`D` で期日を変えると、配置ルールに合うセクションへ自動で移す（移動先はメッセージ
に出す）。合わせずに放置すると次回起動で再配置を提案されてしまうため。
CLI の `todos edit --due` は移動しない（配置の一括評価は `todos rollover` が担う）。

### 追加時の期日の提案

`a` で追加するとき、**見ているセクションが期日で決まるなら期日を入れるか聞く**。

| 見ているセクション | 提案する期日 |
| --- | --- |
| Today | 本日 |
| Tomorrow | 明後日（Tomorrow の配置条件。[decisions.md](decisions.md) 25.1 を参照） |
| InWeek | 当週の**金曜**（それが明後日以前なら聞かない＝水曜以降は聞かない） |
| OpenEnded / ParkingLot | 聞かない（期日で決まらないセクションのため） |

```
 確認  Today のタスクとして期日を 2026/07/28（本日）にしますか？  [y/N]
```

Today や Tomorrow を見ているときに作るタスクは、たいていそのタイミングで
やりたいもの。しかし期日の無いタスクは配置ルールにより ParkingLot へ置かれるため、
作った直後に見失ってしまう。`y` なら提案した期日が入り、そのセクションに残る
（`schedule.section_due` は `desired_section` の逆引きになっている）。

`n` なら期日なしで追加する（従来どおりステータスに応じて OpenEnded か
ParkingLot へ置かれる）。検索結果を表示しているあいだは聞かない。

InWeek だけは週の区切り（日曜）ではなく**金曜**を出す。稼働日として最後になるのは
金曜のため。週の区切りを日曜とする配置ルールそのものは変えない（休日に動かす
こともあるので、日曜までに期日があるタスクは InWeek に入る）。
水曜以降は当週の金曜が Today / Tomorrow の範囲に入るため、InWeek に留まる稼働日が
無くなる。そのときは聞かない。

### 並べ替え

`[` / `]` で、選択中のタスクを**兄弟の中で**上下に動かす（`Shift` + `↑` / `↓`
でも同じ）。子タスクは同じ親の中だけ、トップレベルはセクションの中だけを動き、
端まで来たら止まる。別のセクションへ移すのは `m`。

詳細文と子タスクはタスクに付いて動く。タスク以外の行（見出し直下の覚え書きなど）は
位置を変えない。検索結果を表示しているあいだは並べ替えできない
（並び順が画面と一致しないため）。

並べ替えた順序はファイルの記述順として保存する。`r` の再配置や `m` の移動で
セクション内が並べ替えられると、期日・ステータスが優先されるため崩れることがある
（同じ期日・同じステータスの中では手で付けた順序が保たれる）。

### 複製

`c` で、選択中のタスクを複製して**すぐ下**に置く。大部分が同じで一部だけ違う
タスクを続けて作るための機能。

複製するのは Markdown の**タスク行に書かれているものだけ**
（タイトル・ステータス・相手・期日・タグ）。**詳細文と子タスクは複製しない** —
引き継いだ本文を毎回消すほうが手間になるため。複製後は複製したほうを選択するので、
続けて `i` でタイトルを、`D` で期日を直せる。

TUI から扱えないもの:

- **タスクの削除**: 完了・やらないにしてから `A` でアーカイブする。
  `ops.delete` は archive 経路からしか呼ばない。
- **archive.md の閲覧**: ファイルを直接開く。
- **preamble・未知の見出し配下**: 解析せずそのまま保存する（要件 22.4）。

## モーダル画面

モーダルは中央にタイトル付きの箱として表示する。1 行目はタイトル帯、
最終行は操作の案内を薄く添える。

### 選択モーダル（ステータス変更・セクション移動）

中央に一覧を表示する。`j`/`k` で移動、`Enter` で決定、`Esc` で中止。
数字キーで直接選択もできる。選択肢にはステータス／セクションの記号と色を付ける。

### 入力モーダル（追加・タイトル編集・期日・タグ・検索）

最下行を入力欄として使う。左端に `追加` `検索` などの見出しを帯で示す。
`Enter` で確定、`Esc` で中止。
日本語入力も受け付ける（`get_wch` で 1 文字ずつ読む）。

**カーソルを動かして途中を直せる**（末尾から消し直さずに済むように）。

| キー | 動作 |
| --- | --- |
| `←` / `→`（`Ctrl-b` / `Ctrl-f`） | カーソルを左 / 右へ |
| `Home` / `End`（`Ctrl-a` / `Ctrl-e`） | 行頭 / 行末へ |
| `Backspace` | カーソルの手前を 1 文字消す |
| `Delete`（`Ctrl-d`） | カーソル位置を 1 文字消す |
| `Ctrl-w` | 直前の語を消す（空白区切り） |
| `Ctrl-u` / `Ctrl-k` | カーソルより前 / 後ろを消す |

矢印キーが届かない端末でも直せるよう、`Ctrl` の組み合わせも受け付ける。
入力欄より長い文字列はカーソルに追従して横に送る（末尾のカーソルにも 1 桁使う）。
知らないキーは無視する。編集キーの一覧は `?` のヘルプにも載せる。

### 確認モーダル（再配置・警告の修正）

一覧を見せたうえで `y` / それ以外を聞く（`popup_ask`）。`j`/`k` はスクロールに使い、
閉じる操作にはしない。何をするのかを本文に列挙してから確認する。

### 表示モーダル（詳細・警告・ヘルプ）

中央に枠付きで表示する。`j`/`k` でスクロール、**それ以外のキーで閉じる**。
`j`/`k` は末尾・先頭まで来ても閉じる操作にしない（確認モーダルと同じ扱い。
読み進めた勢いでモーダルが消えてしまわないようにするため）。

箱の幅は**見えている行ではなく全行**から決める。スクロールのたびに幅が変わると、
読んでいる文章が組み替わって見えるため。
警告モーダルは、直せる問題があれば修正内容を並べて確認モーダルとして出す。

詳細モーダルには ステータス / 期日 / タグ / セクション / 詳細文 / 子タスク を並べる。
詳細文は端末幅に合わせて折り返す（切り詰めない）。折り返しは空白を優先し、
空白が無ければ文字単位で折る。

### 確認（y/N）

最下行に `確認` の見出しと `[y/N]` を表示する。`y` 以外は「いいえ」として扱う。

## 検索 UI

`/` または `t` で入力欄を開き、確定すると右ペインが検索結果表示に切り替わる。
検索結果の各行にはセクション名を `[Today]` の形で前置する。

`Esc` またはセクション移動で通常表示に戻る。

## ステータス選択 UI

7 つの固定ステータスを一覧表示する。
`要返答` / `回答待ち` を選ぶと、続けて相手の入力欄が開く（空欄可）。
`完了` / `やらない` を選んだ場合は `d` / `x` と同じ経路を通り、
未完了の子タスクがあれば確認する。

## 再配置の提案

起動時、いまの配置と配置ルールが食い違うタスクが1件でもあれば再配置を提案する
（判定方法は [`docs/decisions.md`](decisions.md) の「日付更新の検出方法」）。

確認は**モーダルで一覧を見せてから**行う。件数だけでは何がどこへ動くのか
判断できないため、次の3点を出す。

- タスクごとの 理由 / 移動元 → 移動先 / タスク名
- 配置ルールの要約（`schedule.RULE_SUMMARY`）
- 中止した場合の挙動（配置は変わらず、次回も提案される）

```
╭─ タスクの再配置 (3 件) ────────────────────────────────╮
│  日付が変わり、いまの配置がルールと食い違っています。  │
│                                                        │
│  理由              移動                    タスク      │
│  期日なし          Today → ParkingLot      あとで読む  │
│  期日なし・仕掛中  Today → OpenEnded       API を実装  │
│  明日が期限        Tomorrow → Today        レビュー    │
│                                                        │
│  配置ルール: 期限切れ・本日・明日が期限は Today、…     │
│                                                        │
│  y で実行   他のキーで中止   j/k スクロール            │
╰────────────────────────────────────────────────────────╯
```

`y` だけが承諾。`j` / `k` はスクロールに使い、閉じる操作にはしない
（長い一覧を読もうとして中止してしまわないようにするため）。
幅が足りない端末ではタスク名と移動先を2行に分けて出す（タスク名は切り詰めない）。

実行後は**何が動いたかを結果モーダルで出す**。背景には移動後の配置を描く。
起動直後の提案でも、先に一覧を描いてから確認する（空の画面で問われても
判断できないため）。

理由の文言は `schedule.reason()` が返す。期限切れ / 本日が期限 / 明日が期限 /
明後日が期限 / 今週が期限 / 来週以降が期限 / 期日なし / 期日なし・仕掛中。

### 毎回提案される場合

配置ルールと食い違いがある限り提案は出続ける。原因は 2 つある。

- **中止した**: 状態ファイルを持たないため「今日は断った」を記録できない。
  食い違いは残るので次回も提案する。
- **手動で移動した**: `m` でルールと違うセクションへ移したタスクは、
  要件 11.6 のとおり毎回再評価の対象になる（仕様として許容している）。
  提案を止めるには期日を設定してルールと一致させるか、`--no-prompt` で起動する。

## 詳細文の扱い

タスク行の直下にインデントして書かれた行は詳細文として扱う（`Task.detail`）。
一覧は 1 タスク 1 行のため詳細文そのものは出さず、`≡` で有無だけを示す。

| 操作 | 詳細文 |
| --- | --- |
| 一覧 | 本文は出さない。持っているタスクに `≡` を付ける |
| `Enter`（詳細モーダル） | 全文を折り返して表示する |
| `i`（タイトル編集） | 触らない |
| `I` | 詳細文だけを外部エディタで編集する |
| `e`（外部エディタ） | タスク行・詳細文・子タスクをまとめて編集する |
| `/`（キーワード検索） | 検索対象に含む（タイトルと詳細文を見る） |
| `c`（複製） | 複製しない（タスク行だけを複製する） |
| ステータス変更・移動・並べ替え・アーカイブ | そのまま保持する |

`I` はタイトル・ステータス・子タスクに触らないため、Markdown の書式を知らなくても
詳細文を書き換えられる。空にして保存すると詳細文を削除する。
箇条書き（`- ` `* ` `+ `）で始まる行は子タスクと区別できないため受け付けず、
変更を破棄して警告する。子タスクを増やしたい場合は `e` を使う。

複数行の入力欄は持たないため、`I` と `e` はどちらも `$EDITOR` / `$VISUAL` を必要とする。
未設定の場合はその旨を表示する（詳細文は CLI の `todos edit --detail` でも編集できる）。
設定方法は [`docs/cli.md` の「外部エディタの設定」](cli.md#外部エディタの設定)を参照。

## 外部ファイル更新の検出

MVP では自動検出しない。要件 24-8 のとおり、TUI 起動中に外部から
tasks.md を編集した場合の対応は保証しない。

`R` キーでファイルを読み直せる。読み直すと選択位置は先頭に戻る。

TUI 側の操作は 1 操作ごとに tasks.md へ書き戻すため、
外部編集と競合した場合は後から書いた方が残る。

## 端末サイズが不足する場合

幅 40 桁・高さ 10 行を下回る場合は描画をやめ、
`端末が小さすぎます (40x10 以上必要)` と表示する。
端末を広げれば通常表示に戻る（リサイズは自動で追従する）。

## 対応環境

- UTF-8 を扱える端末（xterm 系、iTerm2、Terminal.app、GNOME Terminal、tmux など）
- 罫線がずれる場合は環境変数 `TODOS_AMBIGUOUS_WIDTH=2` を指定する
- 記号（`● ▍ ✓` など）が表示できない端末では `TODOS_TUI_GLYPHS=0` を指定する
- 色付きの表示には 256 色端末（`TERM=xterm-256color` など）が望ましい

## MVP 対象外

- Vim 互換のモードやコマンド
- 高度な複数行インライン編集
- Undo / Redo
- 任意のキー設定変更
- マウス操作・ドラッグ操作
- Markdown の完全な装飾表示
- 複雑な画面分割
- プラグイン機構
